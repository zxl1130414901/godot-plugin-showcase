# Godot 插件图鉴 · 设计说明

面向「要给 Godot 项目挑插件」的开发者，把 300 个仍在维护的仓库压缩成可比较、可筛选、可并排的信息面。定版数据来自真实 manifest，300 条全部配有中文短档案与详情档案，未分类 0 条。

## 1. 信息架构

```
#/                选型入口（场景 + 约束 + 结果）
#/all             全部插件矩阵（表格式浏览）
#/repo/<id>       单仓库档案
#/compare?ids=... 并排对比（2–4 个）
```

四层之间是「宽 → 窄 → 深 → 横向」的关系：

| 层 | 回答的问题 | 主要控件 |
| --- | --- | --- |
| 首页 | 我这类需求有哪些候选？ | 大搜索框、场景卡、约束 chips |
| 矩阵 | 300 条里符合硬条件的还剩谁？ | 排序表头、多维下拉、实时过滤 |
| 详情 | 这一个到底能干什么、有什么坑？ | 双栏：正文 01–08 + 评分侧栏 |
| 对比 | 这几个差在哪，选谁？ | 4 列网格、逐行差异高亮、最优标记 |

不引入第三方路由：`#/` 前缀在 `file://` 下无需服务端配合，双击即用。

### 1.1 数据分层

- `manifest.json`（300 条）→ 索引层字段，够撑起搜索、筛选、排序、卡片、对比表。
- `data/rows/row_<id>.json` → 中文短档案：描述、分类、标签、短评、评分。
- `data/details/<id>.json` → 档案层长文，只给详情页与搜索的深层匹配用。
- 三者在构建期由 `scripts/build-data.mjs` 以 `id` 合并成单个 `src/data/catalog.json`。

这样做的原因：300 条索引常驻内存没问题，但把长文本收敛进同一份 JSON 后，前端只依赖一个静态 import，`file://` 单文件产物不需要运行时请求；合并脚本对坏文件与缺失条目不阻断，数据流水线可以在写入过程中随时重建。

降级规则（定版 300/300 齐全，当前未触发，保留为数据回流时的兜底）：无 row → 英文 `description` 兜底 + 评分为「—」+ 分类 `uncategorized`；无 detail → 详情页保留 8 个分区、用短档案字段兜底并显示「档案撰写中」。`hasRow` / `hasDetail` 两个布尔位是前端所有降级分支的唯一依据。

## 2. 三条用户路径

**A. 我知道我要做什么（场景优先）**
搜索框直接输入「对话」「存档」→ 或点场景卡「状态机与逻辑」→ 结果区出现候选 → 勾选约束「Godot 4 原生支持」「无需编译」→ 缩小到 2–3 个 → 进详情看坑 → 加入对比。

**B. 我只看客观指标（矩阵优先）**
`#/all` → 按星标排序 → 过滤「许可证 MIT」「不需要编译」→ 关键词实时收窄 → 直接点进详情或丢进对比。

**C. 我已经有几个候选（对比优先）**
任意页面用 `+ 对比` 收集（全局托盘记忆）→ 托盘点「并排对比」→ 对比页逐行高亮差异，评分行标出唯一最优 → 移除某个再看剩余两两差异。

三条路径共用同一个筛选状态模型（类别 / 版本 / 编译 / 许可证 / 关键词 / 排序），避免用户在页面之间丢失上下文。

## 3. 页面设计

### 3.1 首页

- **Hero**：一句话定位 + 搜索框。搜索框是视觉重心（最大字号、最高对比），下方给 6 个高频词做「零输入也能开始」。
- **场景卡**：12 个真实分类（UI 与界面、状态机与逻辑、网络与联机、存档与数据、AI 与生成、编辑器效率、3D 与着色器、音频、可视化脚本、平台与导出、性能与调试、资源管线），名称与命中数均来自 `catalog.categoryCounts`，不写死。定版计数：state-logic 54、editor-tool 46、3d-shader 34、ui 31、asset-pipeline 28、visual-script 21、platform-export 21、ai-gen 19、debug-perf 18、network 17、save-data 6、audio 5。点击即切换 `category` 筛选，再次点击取消；计数为 0 时卡片置灰。
- **约束区**：`Godot 4 原生支持`、`无需编译`、`有中文档案`、`10 分钟装完`(installComplexity ≤ 3)、`星标 > 500`。做成 toggle chips 而非下拉，因为这是「硬门槛」，需要一眼看到开与关。
- **结果区**：卡片网格，每张卡给「一句话定位 + 星标 / 版本 / 安装成本 / 综合分 + 首个坑 + 档案链接 + 对比按钮」。坑放在卡片上是有意的：选型时最容易忽略的就是坑。

### 3.2 全部插件矩阵

- 表头 sticky，点击列头切换排序：综合评分 / 星标 / 更新时间 / 安装复杂度；`aria-sort` 同步，再点同一列反向。
- 列级响应式：`hide-md`（375–820 隐藏 Fork/许可证）与 `hide-sm`（<600 隐藏语言/创建时间），表格容器横向滚动兜底。
- 每行保留「一句话定位」而不是只有仓库名——纯名字在 300 行里不可读。
- 筛选器与首页共用 `filterRepos`，所以「首页筛完切到矩阵」结果一致。

### 3.3 详情页 `#/repo/<id>`

- Hero：返回矩阵、类别色点、Godot 版本 / 编译 / 许可证 badges、`h1` 仓库名、owner、tagline、summary、GitHub 外链、`+ 对比`、当前档案标识、5 项事实条（星标 / Fork / 安装 / 更新 / 综合分）。
- 正文固定八段编号，顺序即决策顺序：
  01 能做什么 → 02 适用场景 → 03 能力边界 → 04 安装与使用流程 → 05 优缺点 → 06 常见坑 → 07 与谁比怎么选 → 08 证据与链接。
- 侧栏 sticky：六维雷达图 + 六条评分条 + 权重说明 + 安装速览 + 对比入口。雷达给「形状直觉」，评分条给「精确读数」。
- `id` 不存在时给空状态与回矩阵入口，不白屏。

### 3.4 对比页

- 最多 4 个并排，`--cols` 控制网格列数；375 宽下对比项列固定在左侧（`position: sticky`），表格容器横向滚动查看其余列，页面本身不横向溢出。
- 25 行分三组：
  - 事实（10）：类别、Godot 版本、星标、Fork、最近更新、安装复杂度、是否需要编译、许可证、语言、中文档案。
  - 评分（7）：六个维度 + 综合评分。
  - 判断（8）：一句话定位、适用场景、典型用法、优点、缺点、常见坑、与谁比怎么选、什么情况别选。
- 差异高亮逻辑在 `buildCompareRows`：文本行去重后长度 > 1 即 `differ`；数值行只在出现唯一最优时 `bestIndex`，并列或缺失留空。安装复杂度是「越低越好」，用 `higherIsBetter = false`。
- 每列顶部可移除、可清空；URL 即状态（`#/compare?ids=a,b,c`），刷新与分享都不丢。

## 4. 视觉语言

- **主色**：Godot 蓝 `#478cbf`，深蓝 `#2b6b9a` 用于文字与 hover；纸面 `#f4f7fa`，卡片纯白。
- **语义色**：好 `#2f9e63`、警告 `#c9821a`、危险 `#c4453d`、中性 `#8595a6`。只用于 badge 与评分，不做大面积底色。
- **分类色**：12 个 `.cat-0` … `.cat-11`，另加 `.cat-muted` 给 `uncategorized`，只在场景卡与列表的分类小点出现，保持整体克制。
- **字体**：系统字体栈（`-apple-system, "Segoe UI", "Microsoft YaHei", …`），不引外部字体——离线可用且没有 FOUT/CLS。
- **图标**：27 个内联 SVG（`src/components/Icon.tsx`），不引图标库，减少一个依赖也避免 `file://` 下的加载失败。
- **安装成本**：5 点 meter，点亮数量等于 `installComplexity`，并附文字与 `sr-only` 说明，不靠颜色单独传达。

## 5. 响应式

断点：1080 / 900 / 820 / 700 / 600 / 420。

- 375 宽是第一目标：所有容器 `max-width: 100%`，网格用 `minmax(0, 1fr)`，长 URL/仓库名 `overflow-wrap: anywhere`。
- 表格是唯一允许横向滚动的区域（`matrix-scroll`），其余页面不得出现 `scrollWidth > clientWidth`。
- 头部导航在 820 以下折叠为图标条目，对比托盘在 600 以下改为可横向滚动的 chips 行。
- 详情页在 900 以下由双栏变单栏，侧栏评分挪到正文之后（先结论后数据）。

## 6. 技术取舍

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 构建 | Vite + React + TS | 开发反馈快，产物可完全内联成单文件 |
| 路由 | 手写 hash 路由 | 无依赖；`file://` 下 history API 不可用 |
| 状态 | 模块级 store + `useSyncExternalStore` | 对比选择跨页面共享，且快照引用稳定、不触发多余渲染 |
| 持久化 | localStorage + try/catch | `file://` 下可能被禁用，失败必须静默降级 |
| 纯函数分层 | `lib/` 全部无 React 依赖 | 排序 / 筛选 / 搜索 / 评分 / 对比行可直接单测 |
| 单文件产物 | 构建后 Node 脚本内联 | 见下节 |

### 6.1 离线单文件的关键约束

`scripts/inline.mjs` 在 `vite build` 之后做四件事：

1. 删除 `<link rel="modulepreload">`，把 CSS 内联进 `<style>`。
2. 把 `<script type="module" crossorigin src=...>` 的内联版本改成经典脚本 `(function(){'use strict'; … })();`，并**移动到 `</body>` 前**。原因：经典脚本没有 `defer`，留在 `<head>` 会在 `#root` 出现之前执行，`createRoot` 拿不到节点直接白屏。
3. 校验产物：不允许 `type="module"`、`crossorigin`、`import.meta`、外链 `<script src>`、`<link rel="stylesheet">`、`@import`、外部字体 URL；`#root` 必须存在且脚本位于其后。校验时先剥离脚本文本，避免把库代码里的字符串误判成标签属性。
4. 删除 `dist/assets`，只留 `index.html`。

`vite.config.ts` 里 `inlineDynamicImports: true`、`cssCodeSplit: false`、`modulePreload: false`、`base: './'` 是配合项。

## 7. 可访问性

- 交互控件均为原生 `button` / `a` / `input` / `select`，键盘可达。
- 对比按钮用 `aria-pressed` 表达选中态；满 4 时 `disabled` 并给 tooltip 文案。
- 排序表头用 `aria-sort`，图标旁保留文字标签。
- 所有装饰性 SVG `aria-hidden="true"`；雷达图给 `aria-label` 写明六维分值。
- 安装 meter 与评分条都有 `sr-only` 文本替代。
- 焦点样式统一 `:focus-visible` 蓝色描边，不依赖 `outline: none`。

## 8. 演进点

1. 数据更新：rows / details 变动后重跑 `npm run build`，无需改前端代码。
2. 300 条时矩阵直接渲染（已实测）；若涨到 1000+ 再加分页或虚拟滚动。
3. 搜索可升级为带权重的字段匹配（现在 `matchesQuery` 是分词后 AND 全字段包含，够用且可测）。
4. 对比页可加「导出为图片/文本」，服务于团队评审。
5. 分类色可增加更细的二级区分，提高密集列表的辨识度。
